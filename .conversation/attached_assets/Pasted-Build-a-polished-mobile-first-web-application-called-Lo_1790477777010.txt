Build a polished mobile-first web application called **Location Wrapped**.

## Product concept

Location Wrapped is a personal location-history app inspired by the storytelling style of Spotify Wrapped.

Instead of requiring users to import old location history, the app begins building their history from the moment they enable location tracking.

The full product flow is:

Onboarding → Enable Location Tracking → Collect Location Data → Process Visits → Dashboard → Map → Wrapped → Share

We will build this incrementally.

For this step, implement **Wave 1 only: product foundation, visual design, onboarding, navigation, and location permission flow.**

Do not implement the entire backend or Wrapped system yet.

## Design direction

Use a **Vibrant Wrapped** visual theme.

The app should feel:
- bold
- playful
- modern
- highly visual
- personal
- polished
- mobile-first

Do not make it look like a corporate analytics dashboard.

Use:
- oversized typography
- colorful gradients
- dark backgrounds
- rounded cards
- abstract shapes used sparingly
- subtle animations
- large statistics
- smooth mobile interactions

Suggested palette:

- Deep navy: `#0B0B14`
- Electric purple: `#7C3AED`
- Hot pink: `#EC4899`
- Bright orange: `#F97316`
- Electric blue: `#2563EB`
- Lime: `#A3E635`
- Off-white: `#F8FAFC`

Use Space Grotesk, Inter, or another modern geometric sans-serif font.

## Design system rules

The interface should feel intentionally designed and consistent rather than like a collection of AI-generated components.

Follow these rules throughout the app:

- Use an **8px spacing system**.
- Use **16px horizontal page padding** on mobile.
- Use one primary card radius consistently throughout the app.
- Use a limited number of card styles and reuse them.
- Reuse the same button, header, card, and navigation patterns across screens.
- Prefer typography, spacing, hierarchy, and composition over decorative effects.
- Keep shadows subtle.
- Avoid unnecessary borders.
- Avoid excessive glassmorphism.
- Avoid gradient borders.
- Do not put gradients on every card.
- Reserve strong gradients for hero sections, onboarding moments, and Wrapped screens.
- Limit each normal app screen to one dominant accent color.
- Avoid random decorative blobs, floating shapes, or ornaments unless they serve the composition.
- Avoid excessive emoji in the interface.
- Avoid overly rounded elements everywhere.
- Avoid creating unique one-off components when an existing component can be reused.
- Keep icon style consistent across the entire app.
- Keep typography scale consistent across screens.
- Maintain consistent header spacing and vertical rhythm.
- Do not overcrowd screens with cards.
- Use whitespace intentionally.
- Do not make every metric its own tiny card.
- Use large, editorial statistics when a number is important.
- Normal app screens should feel restrained and refined.
- The Wrapped experience can be more expressive, colorful, and experimental.

The product should have two related visual modes:

**Core app**
- clean
- refined
- dark
- map-focused
- calm
- structured

**Wrapped experience**
- bold
- editorial
- colorful
- animated
- expressive

Both should clearly belong to the same product.

**Start My Wrapped**

## Onboarding

After tapping Start My Wrapped, guide the user through a short onboarding experience.

### Screen 1

**Your year starts here**

Location Wrapped records the places you visit so you can look back on where your year took you.

### Screen 2

**Built around your privacy**

Explain clearly that location tracking requires permission and that users can stop tracking or delete their data.

### Screen 3

**Enable Location Tracking**

Button:

**Allow Location Access**

Use the browser Geolocation API to request permission.

If permission is denied, show a friendly recovery state explaining how to enable it later.

Never show raw browser errors.

## Tracking status

Once permission is granted, show:

**You're tracking**

Supporting text:

Your Location Wrapped starts building from here.

Create a tracking status component showing:

- Tracking active/inactive
- Last location recorded
- Last update time

For Wave 1, location collection can be basic and mostly frontend-focused.

The Try Demo button should load realistic fake location history so evaluators can immediately explore:

Map

## Architecture

Prepare the app for the following data pipeline:

Raw GPS records  
↓  
Location processing  
↓  
Visits  
↓  
Places  
↓  
Statistics  
↓  
Wrapped presentation

Keep location processing logic separate from UI components.

Prepare modules/services such as:

- locationTracker
- locationService
- visitProcessor
- statisticsService
- wrappedGenerator

## Component system

Create reusable components for:

- buttons
- page headers
- statistic displays
- cards
- place summaries
- tracking status
- bottom navigation
- Wrapped progress
- map detail sheets

Do not duplicate visual patterns unnecessarily.

If two elements serve the same purpose, they should generally use the same component or design pattern.

## Important restrictions

Do NOT implement:

- Google Timeline import
- live family tracking
- social networking
- messaging
- payments
- AI chat
- leaderboards
- friends/followers

Also avoid these visual patterns unless absolutely necessary:

- heavy glassmorphism
- glowing borders
- gradients on every component
- oversized shadows
- random neon effects
- excessive pills
- excessive floating cards
- generic dashboard grids
- decorative elements without purpose

Do not redesign the app beyond the specifications above.

The goal of Wave 1 is to create a polished product foundation with onboarding, location permissions, tracking-state UI, navigation, and demo data.

Prioritize **consistency, hierarchy, restraint, and reuse** over adding extra visual effects.
